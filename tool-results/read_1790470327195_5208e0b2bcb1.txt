   364→## Phase 2: Identity, Authentication & User Architecture — PLAN
   365→
   366→**Date:** 2025
   367→**Task ID:** P2-PLAN
   368→**Description:** Comprehensive audit of existing auth architecture and detailed implementation plan for Phase 2.
   369→
   370→### Audit Findings
   371→
   372→14 weaknesses identified (W-1 through W-14). Critical: 7-day JWT with no rotation/revocation, token in localStorage, no server-side logout, no email verification, no password reset, no account lockout, CORS wildcard.
   373→
   374→### Plan Produced
   375→
   376→11-section plan covering:
   377→1. Current auth architecture audit
   378→2. Recommended identity architecture (dual-token, organizer profiles, membership-based staff)
   379→3. Role/permission model (code-defined permissions, 4 roles, centralized authorization functions)
   380→4. Organizer/tenant model (OrganizerProfile 1:1 with User, Event.organizerProfileId migration)
   381→5. Staff membership model (OrganizerMembership with JSON permissions, OrganizerInvitation flow)
   382→6. Session/token architecture (15min access token + 7-day httpOnly refresh cookie with rotation)
   383→7. Database changes (6 new models, 2 modified models, 1 deprecated, migration script)
   384→8. API endpoints (10 modified, 21 new)
   385→9. Security improvements (session architecture, account lockout, email verification, password reset, CORS, security headers, password policy, Next.js middleware)
   386→10. Testing strategy (~70 new tests across ~10 files, including security-specific cross-organizer tests)
   387→11. Implementation sequence (15 ordered steps)
   388→
   389→### Key Design Decisions
   390→- Keep jose JWT library (no new auth framework)
   391→- Dual-token system: 15min access (memory) + 7-day refresh (httpOnly cookie)
   392→- Code-defined permissions (no Permission/RolePermission DB tables)
   393→- Rename STAFF → ORGANIZER_STAFF, staff identity via OrganizerMembership not User.role
   394→- OrganizerProfile as separate model from User (onboarding flow)
   395→- Event.organizerId → Event.organizerProfileId (breaking migration)
   396→- All new mutation endpoints use Zod, all protected endpoints enforce server-side authorization
   397→- Anti-enumeration on email verification and password reset
   398→
